# Техническое задание: модуль «Планировка»

## 1. Назначение

3D-редактор для поэтапного моделирования квартиры (первоначально — один этаж) и последующей расстановки электроустановочных изделий и освещения.

Модель помещения, история построения и семантика объектов должны быть **отделены от системы визуализации (рендера)**.

## 2. Режимы работы

**Редактирование:**

- вид сверху — основной;
- изометрический вид — для работы с высотой и навесными объектами;
- ортогональная проекция;
- привязка к сетке 1 см.

**Просмотр:**

- свободная 3D-камера;
- независимое от редактора управление камерой.

## 3. Этапы построения

Редактирование выполняется последовательно. Каждый этап является **одной неделимой Feature**, завершаемой явным **Commit**.

До Commit пользователь может выполнять произвольное количество изменений внутри текущего этапа. Эти изменения не являются отдельными элементами истории.

### Этап 1 — Планировка помещения

- Построение контура помещения.
- Создание и редактирование стен.
- Задание размеров.
- Формирование помещений.
- Создание пола и потолка.
- Привязка к сетке 1 см.

### Этап 2 — Напольные объекты

Расстановка и параметрическое редактирование:

- мебель;
- двери;
- бытовые потребители: плита, стиральная машина, холодильник и т. п.;
- радиаторы;
- прочие напольные объекты.

Для параметрических моделей отображаются маркеры изменения размеров и положения.

### Этап 3 — Навесные объекты

Расстановка объектов, закрепляемых на стенах или потолке:

- окна;
- зеркала;
- шкафчики;
- вытяжки;
- кондиционеры;
- навесные потребители;
- вводной электрощит;
- прочие объекты.

Объекты должны хранить явную зависимость от элемента конструкции, на котором они закреплены.

### Этап 4 — Розетки и выключатели

- Автоматическое предложение точек установки.
- Учитываются:

  - расположенные потребители;
  - геометрия помещения;
  - тип объекта;
  - заданные стандарты и правила;
  - расстояния от стен, углов, проёмов и других объектов;
  - высота установки.

- Пользователь подтверждает или корректирует результат.
- Свободная установка розеток и выключателей.
- Для каждого элемента задаётся назначение.
- Поддержка групп розеток/выключателей.
- Проверка конфликтов с мебелью, дверями, окнами и другими объектами.

### Этап 5 — Освещение

- Расстановка:

  - светильников;
  - ламп;
  - LED-лент;
  - других источников света.

- Указание выключателя или группы выключателей для каждого светильника.
- Поддержка нескольких групп освещения.
- Проверка конфликтов и зависимостей.

## 4. Feature History

История построения аналогична **Feature Tree в FreeCAD Part Design**.

```text
Квартира
├── Планировка помещения
├── Расстановка напольных объектов
├── Расстановка навесных объектов
├── Расстановка розеток и выключателей
└── Расстановка освещения
```

Каждая Feature представляет **атомарный коммит состояния модели**.

Feature содержит:

- тип этапа;
- параметры операции;
- зависимости от предыдущего состояния;
- необходимую для воспроизведения информацию;
- информацию о возникших конфликтах.

При выборе Feature отображается состояние модели, соответствующее этому коммиту.

## 5. Редактирование истории

После изменения ранее созданной Feature все последующие Feature должны быть **пересчитаны относительно нового состояния**:

```text
Feature 1
    ↓
Feature 2 ← изменена
    ↓
Feature 3 ← пересчитана
    ↓
Feature 4 ← пересчитана
```

Если последующую Feature невозможно корректно применить, создаётся конфликт.

Пользователь должен иметь возможность:

- отменить изменение;
- разрешить конфликт;
- изменить зависимый объект;
- удалить конфликтующий объект.

## 6. Зависимости и деструктивные изменения

Объекты, зависящие от геометрии или других объектов, должны иметь явные зависимости.

Например:

```text
Стена #3
 ├── Окно #1
 ├── Кондиционер #1
 ├── Розетка #7
 └── Розетка #8
```

При удалении стены система должна обнаружить зависимости и предупредить пользователя **до Commit**:

> Стена удаляется. На ней закреплены 4 объекта. Продолжить?

Возможные действия:

- отменить;
- удалить зависимые объекты;
- перепривязать объекты;
- оставить конфликт для последующего разрешения.

Незаметное удаление зависимых пользовательских объектов не допускается.

## 7. Архитектура

Модель должна быть независима от 3D-рендера:

```text
Domain Model
    │
    ├── Geometry
    ├── Objects
    ├── Dependencies
    └── Feature History
            │
            ▼
      Editor / Interaction
            │
            ▼
      Renderer Adapter
            │
            ▼
        3D Renderer
```

**Domain Model** не должна содержать объекты или состояние конкретного 3D-движка.

Рендерер должен получать состояние модели и преобразовывать его в визуальное представление.

## 8. Основной пользовательский сценарий

```text
Создать планировку
      ↓
Контур и стены
      ↓ Commit
Напольные объекты
      ↓ Commit
Навесные объекты
      ↓ Commit
Розетки и выключатели
      ↓ Commit
Освещение
      ↓ Commit
Готовая модель квартиры
```

История позволяет вернуться к любому этапу, изменить его и автоматически пересчитать последующие этапы.

## Этапы

| Этап                                | Что реализуется                                                                      | Проверяемый результат                                                          |
| ----------------------------------- | ------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------ |
| **1. Domain Model**                 | Модель квартиры, геометрия, объекты, зависимости, Feature/Commit                     | Модель можно создавать и изменять без UI                                       |
| **2. Renderer foundation**          | 3D-сцена, камера, выбор объектов, преобразование Model → Render                      | Можно отобразить тестовую модель и выбрать объект                              |
| **3. Editor foundation**            | Вид сверху, изометрия, переключение камер, сетка 1 см, snapping, базовые манипуляции | Можно перемещать/редактировать объекты в сцене                                 |
| **4. Feature History**              | Commit, Feature Tree, восстановление состояния, пересчёт последующих features        | `Feature 2 → Feature 3 → Feature 4`, изменение Feature 2 пересчитывает историю |
| **5. Планировка**                   | Контур, стены, помещения, пол/потолок, размеры                                       | Можно построить реальную квартиру                                              |
| **6. Напольные объекты**            | Библиотека параметрических моделей, мебель, двери, потребители, радиаторы            | Можно расставить и изменить размеры объектов                                   |
| **7. Навесные объекты**             | Привязка к стенам/потолку, окна, шкафы, кондиционеры, щит и т. д.                    | Объекты корректно следуют за изменяемой стеной                                 |
| **8. Dependency & Conflict System** | Зависимости, обнаружение деструктивных изменений, разрешение конфликтов              | Удаление стены корректно предупреждает о зависимых объектах                    |
| **9. Электрика**                    | Розетки, выключатели, назначения, группы, свободная установка                        | Можно полностью расставить электроустановочные изделия                         |
| **10. Auto Placement**              | Правила, эвристики, стандарты, автоматическое предложение розеток/выключателей       | Для квартиры генерируется проверяемый набор предложений                        |
| **11. Освещение**                   | Светильники, LED, группы, связи с выключателями                                      | Можно построить схему освещения                                                |
| **12. Free-camera Viewer**          | Свободная камера, итоговый просмотр, скрытие UI редактора                            | Готовую планировку можно нормально осматривать                                 |
